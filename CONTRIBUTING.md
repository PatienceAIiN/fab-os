# Contributing to Fab OS

Thank you for helping. Fab OS is an Ubuntu 26.04 LTS derivative with a KDE Plasma 6 desktop and a built-in
agent, developed by Patience AI. Everything Patience AI wrote is Apache-2.0; contributions are accepted under
the same licence (inbound = outbound).

## Prerequisites

Builds are rootless and run on a laptop with no passwordless sudo.

- **Rootless podman** (the rootfs is a multi-stage `image/Containerfile` on `ubuntu:26.04`).
- **QEMU** (`qemu-system-x86_64` with KVM) and **OVMF** (UEFI firmware) to boot the image.
- `mtools`, `dosfstools`, `sfdisk`, `e2fsprogs` for the rootless GPT/ESP assembly (`scripts/make-disk.sh`).
- `python3` on the host for the agent/feedback unit tests (the image build installs its own Python inside
  the container).
- About 7 GB of free RAM. Every heavy command goes through `tools/rg` (resource guard: RAM cap, CPU quota,
  low priority) so the host desktop is never starved; do not bypass it.
- The AI binaries `aios`/`aiosd` come from the separate `ai-native-os` repository:
  `scripts/stage-ai-binaries.sh` copies or builds them into `build/bin/`.

## Build, boot, test

```bash
scripts/stage-ai-binaries.sh                      # build/bin/aios, build/bin/aiosd
scripts/build-rootfs.sh vm                        # podman build -> build/fabos-root-vm.ext4 (MIRROR=... to use a local mirror)
scripts/make-disk.sh vm                           # UEFI disk image
scripts/boot-vm.sh                                # QEMU window (login fabos / fabos, VM profile only)

tests/boot-test.sh                                # headless boot, serial self-test markers
tests/branding-check.sh vm                        # static checks on the built image (identity, no Canonical branding, legal files)
python3 tests/agent-test.py                       # agent daemon with the scripted provider (no network)
python3 tests/feedback-test.py                    # feedback relay
tests/ui-tour.sh                                  # screenshot tour -> build/screenshots/tour-*.png

scripts/build-rootfs.sh iso && scripts/build-iso.sh   # live/installer ISO (shim + GRUB, Calamares)
tests/iso-boot-test.sh
```

Run `tests/branding-check.sh` and the unit tests before opening a pull request. If you change anything
visible, attach the relevant `tests/ui-tour.sh` screenshots to the PR and say which frames you looked at.

## Rules of the repository

- **Identity strings come from `brand/brand.conf`.** Never hard-code the OS name, vendor, URLs or colours;
  package files use `@DISTRO_NAME@`-style placeholders rendered by `packages/build-debs.sh`.
- **No vendor trademarks in new assets.** No Canonical, KDE, Mozilla or other third-party logos, wallpapers
  or names in artwork, themes, icons, screenshots used as assets, or marketing material. Everything under
  `brand/` must be generated by `brand/gen/` or documented in `legal/ARTWORK.md` with its provenance and
  licence. Referring to upstream projects by name for identification (attribution) is fine and required.
- **Never rebrand attribution.** Copyright notices, About dialogs, licence texts, author credits and
  functional identifiers (package names, D-Bus names, config keys) stay upstream. See
  `legal/PATCHED-BINARIES.md` and ADR-0008/0009 before touching `rebrand-*`.
- **Packages must install and remove cleanly on stock Ubuntu 26.04** as well as on Fab OS.
- **Architecture changes need an ADR** in `docs/decisions/` (next free number).
- **Do not change security posture silently**: unmodified Ubuntu kernel and shim, AppArmor on, no snap,
  no telemetry, agent root access only through `rootexec` with a policy-approved one-time authorization.
- **Never commit secrets or personal data.** `build/` (including `build/secrets/`) is ignored. Use
  `someone@example.com`-style placeholders in examples; the only real addresses in the tree are the
  project contacts `info@patienceai.in` and `support@patienceai.in`.
- The VM profile (autologin, password `fabos`) is for testing only and must never be distributed.

## Developer Certificate of Origin

Every commit must be signed off (`git commit -s`), which adds

```
Signed-off-by: Your Name <you@example.com>
```

and certifies the [Developer Certificate of Origin 1.1](https://developercertificate.org/): you wrote the
change or have the right to submit it under Apache-2.0. Use a real name; a no-reply address is fine.

## Pull requests

Fill in `.github/PULL_REQUEST_TEMPLATE.md`. Keep PRs focused, describe what you verified and how (which
tests, which screenshots), and update `UI_REVAMP_CHANGELOG.md` for user-visible changes and `legal/` if the
set of modified upstream packages or third-party components changes.

## Conduct

This project follows the Contributor Covenant 2.1 (`CODE_OF_CONDUCT.md`). Contact: info@patienceai.in.
